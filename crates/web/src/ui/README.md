# Shared pieces

What every view is built from. One line each: what it is, when to use it, its signature. Each
module's own doc comment has an example. Styles are in the `*.module.scss` beside a piece, and
`../../STYLES.md` says how a view styles around one.

## Contexts

The page has two contexts and no others. Each is read with `expect_context` by the component that
needs it.

| Context                 | Provided                                                                                | Fields                                                                                                                                                                                                                                                                                                      |
| ----------------------- | --------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `app::Global` (`Copy`)  | once, at the page's root                                                                | `link: Link`, the connection to tetherd with the server's state (`link.server`) and the connection's own figures (`link.figures`). `router: Router`, the address: the picked device and the open page. `ui: Ui`, the page's chrome: `panel`, `theme`, `toast`, `confirm`, `adding`, `wanted`, `drops`       |
| `app::Picked` (`Clone`) | for the device's pane and for each view about the device, only while a device is picked | `id: DeviceId`, `device: Signal<Rc<dyn Device>, LocalStorage>`, `listed: Signal<protocol::Device>`, and the services that keep working while the device's views are closed: `board: Board`, `control: Control`, `console: Console`, `feed: Feed`, `routes: Routes`. Every field but `id` is a `Copy` handle |

```rust
let Global { link, ui, .. } = expect_context::<Global>();
let Picked { device, feed, .. } = expect_context::<Picked>();
```

- Nothing that is provided is also passed as a prop or an argument. The one exception is a plain
  function that an event handler or a task calls, which has no owner to read a context from: the
  component reads the context and the handler captures the handle.
- The services are arena state under an owner of the pick's own, which is cleaned up once neither
  the pane nor a view of the old device is left (`app/scope.rs`). That stops them: Follow, the
  shell, this browser's camera capture, a playing route.
- A task that may outlive the pick reads a service's signals with the `try_` methods, since they are
  disposed once another device is picked.
- State that only one open view reads is a hook the view calls, such as
  `views::logs::front::use_front()` for the app in front. It is no service.
- A view about the device is only built while the device offers it (`Needs` in `app/scope.rs`), so
  it never handles "no device" or "not connected" itself.

## Rules

Rules that hold for all the pieces:

- A hook (`use_*`, `kept_signal`, `kept_then`, `Installed::of`) is called while a component is
  built, never in an event handler. Hooks that need the connection or the page's chrome read
  `Global` with `expect_context` themselves.
- Nothing takes a context value as a prop. State a piece shows is owned by the view and passed in,
  such as `sought`, `open` and `renaming`.
- "Not loaded" is `Loadable::Loading`, never an empty list. "Nothing chosen" is `None`, never `""`.
- A `>` in a prop's value ends the tag in `view!`, so a closure with `Option<T>` in its arguments,
  or a `>=`, is made before the `view!` or goes in braces.
